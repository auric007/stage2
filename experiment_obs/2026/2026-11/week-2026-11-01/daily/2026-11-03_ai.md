## Learning note: why different models find different objects even at the same recall, and how to use it
Evidence (115 scenes, IoU 0.3): [COMPLEMENT_shipped115_ai.md](../experiments/EXP-2026-11-02-01-dino-arch/COMPLEMENT_shipped115_ai.md). Code: `code/complement.py`.

### 1. Recall is a count; it doesn't say which objects
- Two models with 60% recall can share almost all their hits, or almost none. What matters for combining them is the **overlap of their found sets**.
- Measure it with the **Jaccard** index: both ÷ (found by either).
- Our numbers:
  - **exp15 vs exp09 (missile): Jaccard 0.96.** 246 missiles found by both, 1 only by exp15, 8 only by exp09. Both are fine-tunes of the same YOLOv8m, ensembled with the same YOLO11l, trained on the same data. They learned nearly the same thing, so combining them is almost useless (union 61.7 vs 61.5).
  - **ft6 vs new_ens_last (radar): Jaccard 0.87.** Same family, different seeds and checkpoints; union 70.4.
  - **HYBRID (YOLO) vs DINO: Jaccard 0.27–0.73.** Different architectures:
    - smallvehicle: each finds about 63%, but only 597 of 1242 are common. **Union 78.2%**: 189 found only by DINO, 185 only by the HYBRID.
    - arty: Jaccard 0.27;
    - logistic: 0.42;
    - vehicle: 0.52.
- **Rule of thumb.** Combining two models helps in proportion to "only B": what B finds that A misses. Low Jaccard plus decent precision is the signal to ensemble.

### 2. Why do models disagree? What each one learns
- **Architecture and input view.**
  - YOLO (CNN) runs on the 0.30 m grid with 4 TTA views. It learns local texture and shape at a fixed object size.
  - DINO (ViT-H, self-supervised pretraining) runs on native pixels. Attention across a 512 px tile gives it global context and robust features.
  - The two fail on different objects: different scale, blur, rotation, clutter.
- **Localization and classification are two separate skills.** Section 2 of the evidence: how often a box is there at all vs with the right class.

  | class | HYBRID: any box | HYBRID: right class | DINO: any box | DINO: right class |
  |---|--:|--:|--:|--:|
  | missile | 92.5 | 59.8 | **98.1** | 38.3 |
  | vehicle | 88.5 | 84.7 | 92.6 | 47.1 |

  - DINO localizes **better** than the HYBRID for every class. Its class decision is worse, which is why M2 (DINO boxes, HYBRID class) works.
- **What the label policy teaches.**
  - DINO calls 122 test missiles "camo". It was trained on the old labels, where camouflaged things were labelled camo.
  - DINO calls 821 vehicles "logistic": its loss weighted vehicle ×0.35.
  - A model learns the training labels' rules and the loss weights, not "the truth". M1 retrains on the official labels to test this; after its first epoch, val vehicle F1 rose 29.7 → 69.6.
- **What is not in the pixels.**
  - Missile **MLRS** (82 test objects, SOC "Nil"): about 25% recall for every model (DINO 6%).
  - Missile labelled from **Site** or **Third_Party** evidence: 47–65% recall vs 72% for "Pixels".
  - Radar **EWS**: 21%.
  - No model can learn what the image doesn't show. Those misses are shared, and ensembling can't fix them; they need data or label work.
- **Same backbone and same data means the same mistakes.** Seeds and checkpoints shift the threshold a little (ft6 vs new_ens_last: 18 vs 8 unique radars) but don't change what is learned.
  - Multi-seed averaging mainly **calibrates the score**, which helps precision at a given recall.
  - A different architecture, input or training data **changes which objects are found**, which helps recall.

### 3. How to use this to boost metrics
1. **Before ensembling, measure the overlap per class.** Use `complement.py`: both / only A / only B / union.
   - The union recall is the ceiling an ensemble can reach for that class: smallvehicle 78.2, radar 74.5, camo 73.6.
   - If "only B" is near 0, skip B.
2. **Choose the fusion that matches the type of disagreement:**
   - **Same boxes, different class** (localization good, class bad) → take the boxes from one model and the class from the other (M2). This works for arty, radar and vehicle.
   - **Different boxes** (each finds objects the other misses) → union: add B's boxes where A has none (M3). This works for smallvehicle, camo and tank.
   - **Same family, same boxes** → average the scores (avgall/noisy-or) to calibrate. Expect precision gains, not recall.
3. **Decide per class.** No single fusion is best for all 8 classes; that is why ENS picks per class.
4. **Then handle cross-class conflicts.** The merge removes duplicates but can delete correct boxes (27 missiles lost to radar). Check what the merge removes per class pair, as in the radar-vs-missile study.
5. **Shared misses** (MLRS, EWS, Site-based labels) need data, not ensembles. Track them separately so they don't hide inside the "recall" number.
